# QA-bewijs

- Website / scope / wijziging:
- Level en risico; reden voor selectie:
- Tijd / commit / bronhash / dirty state:
- Omgeving: Node, dependencies/lockfile, browser, OS/fonts, viewport:
- Commando's en rapportpaden (V2 record.json indien beschikbaar):
- Werkelijk uitgevoerd: controles, states, resultaat, aantallen en skips:
- Hergebruikt bewijs: oorspronkelijke datum/hash, reden dat het nog geldig is:
- Retest-triggers: betrokken bronnen/config/deps/omgeving/regressiesignaal:
- Console / Formspree-bescherming / lokale links:
- Axe: critical/serious/moderate/minor + incomplete checks:
- Visuals: beoordeelde verschillen, referentie-update indien geautoriseerd,
  normale vergelijking zonder update:
- Lighthouse: desktop/mobiel, targets, metrics, concrete fouten versus kansen,
  lokale beperkingen (of waarom niet nodig op LIGHT/MEDIUM):
- Handmatig: keyboard/focus, responsive, volledige scrollreview, SEO, claims:
- Ongeteste onderdelen / open problemen / warnings:
- Git diff/status en behouden bestaand werk:
- Eindoordeel: PENDING / FAIL / PASS met concrete onderbouwing.

Een groen script, discovery of plan alleen is nooit FINAL PASS.
